# Change Log — Audit Remediation Pass

Every change below traces to a numbered finding in the two audit reports. Where I disagreed with a
recommendation, or found something the audits missed, it is called out explicitly.

**Verified before/after on a real production build.** Build: ✅ 959 static pages · TypeScript: ✅ clean ·
ESLint (incl. `jsx-a11y`): ✅ zero warnings · Data integrity: ✅ passing.

## 🔴 Launch blockers — all resolved

### 1.1 Fabricated "Evidence Card" on 200 pages → evidence-gated system

The single biggest liability. An identical hardcoded card reading *"Test Date: 2026-08-01 · Evidence
Type: Hands-on + Vendor Data"* rendered on **every** tool page, including the 153 generated by
`scripts/gen-tools.mjs` with `reviewsCount: 0`.

**What I built** — a three-level verification system where the claim is structurally impossible to fake:

| Level | Meaning | Score shown? |
|---|---|---|
| `hands-on-tested` | We ran it; requires `testedAt` + `scores` + `evidenceUrls` | ✅ |
| `pricing-verified` | Price confirmed on vendor page; requires source URL + date | ❌ |
| `listed-only` | Catalogued from public info — the honest default | ❌ |

- New `src/data/verified-tools.ts` is the **only** place a level above `listed-only` can be granted.
  Seed data is typed as `ToolSeed`, which structurally *cannot* declare its own verification.
- `EvidenceCard` renders only for genuinely tested tools; everything else gets `NotTestedNotice`.
- CI (`npm run validate:data`) **fails the build** if anything claims `hands-on-tested` without a
  date, scores and published evidence.

> **Deliberate decision:** I left the hands-on registry essentially empty. Populating it with
> invented test data would have recreated the exact violation being fixed. All the plumbing —
> Evidence Card, score radar, "Tested only" filter, `Review` schema, badge — activates the moment
> you add your first real entry. `DEPLOYMENT.md` has the workflow and a suggested first ten.

**Verified:** `curl /tool/sora | grep -c "Evidence Card"` → **0** (was 1 on all 200).

### 1.2 `aggregateRating` structured-data spam → gated on real reviews
`ratingCount: Math.max(tool.reviewsCount, 1)` told Google *"1 person rated this 4.8"* on 153 pages
with zero reviews. Now `aggregateRating` is emitted **only** with ≥3 genuine approved reviews, read
live from the database (`src/lib/reviewStats.ts`), failing closed if unavailable. Editorial `Review`
schema is emitted only for tested tools.
**Verified:** 0 occurrences across untested pages.

### 1.3 🔓 Site defacement vulnerability → RLS locked down
`site_settings` had `FOR UPDATE USING (true)`. The anon key is public in the browser bundle — **any
visitor could rewrite your hero text, banner or footer to spam/malware from the console.** Same
pattern let anyone self-approve reviews (bypassing moderation *and* rate limiting), flood
`click_log`, and spam the newsletter table.

- `supabase/migrations/0003_lock_down_rls.sql` revokes all anon writes (plus explicit `REVOKE`s).
- New `src/lib/supabaseAdmin.ts` (service role, `import 'server-only'` so the build fails if it ever
  leaks into client code). **All 8 write paths migrated.**
- `reviews.status` now defaults to `'pending'` at the database level as defence in depth.

### 1.4 ⭐ `/tools` served Google an empty page → Server Component
The most important SEO page was `<Suspense><ToolsClient /></Suspense>` with everything client-side.
Rewrote as a Server Component with a small filter island and **real `<a href>` pagination** (the old
"Load More" button meant 176 of 200 tools were uncrawlable).

**Verified:** `curl /tools | grep tool-links` → **0 → 24 tools + pagination to page 9.**

### 1.5 Broken outbound links → fixed + permanent monitoring
I re-tested all 12 with `curl` rather than trusting the report — every finding confirmed.
- **9 repaired** (root cause: generator prefixed `www.` onto `.ai` domains that don't have it).
- **3 confirmed dead** and removed from the catalog entirely. I researched each before burying it:
  Play.ht (Meta acqui-hire, terminated 2025-12-31), Hour One (folded into Wix), Morningfame (parked domain).
- New weekly cron `/api/cron/link-health` + `vercel.json` schedule.

> **I also checked the 161 `www.` URLs the audits never tested** — all resolve fine, so I tuned my
> validator away from a false-positive heuristic to a precise known-dead-host check.

### 1.6 Fake affiliate links → honest handling
15 tools carried guessed `?via=creatoraihub` params for programs never joined: **every click earned
nothing** while the footer claimed a commercial relationship. Added `affiliateProgram` field —
`/go/[slug]` now ignores `affiliateUrl` unless a real program is set, and `rel="sponsored"` is
applied conditionally. `/disclosure` **auto-detects and states the true position.**

### 1.7 Zero analytics → installed | 1.8 No security headers → full set
`@vercel/analytics` + `@vercel/speed-insights` (cookieless). Full CSP, HSTS, X-Frame-Options,
Referrer-Policy, Permissions-Policy. **Verified live via `curl -I`.**

### 1.9 Rate limiter broken on serverless → Upstash-backed
In-memory `Map` doesn't work across lambda instances. Added distributed limiting via Upstash REST
(plain `fetch`, **no new dependency**) with automatic in-memory fallback.

### 1.10 Hardcoded URL in 5 files → single source of truth
`src/config/site.ts`. Moving domains is now one env var. Contact email derives from the host so it
can't contradict the domain again.

## 🟠 Data & content quality

- **2.1 Rating inflation** — 200 tools rated 4.1–4.9, none below 4.0, five stars unable to resolve
  that range. Replaced with 5-dimension scoring (0–10, **computed** weighted average, never
  hand-adjusted) + mandatory `pros`/`cons`. CI warns if a tested tool lists no cons.
- **2.3 Wrong pricing** — OpusClip was listed at `$9.99/mo`; **researched and corrected to `$15/mo`**.
  Prices now carry a clickable source URL and check date.
- **2.2 / 5.1 Images** — all raw `<img>` replaced with `next/image` via a `SmartImage` wrapper with
  graceful fallback (favicon services 404 often). Fixes CLS, adds AVIF/WebP + responsive srcset.

## 🟡 SEO — sitemap 223 → 554 URLs

| Added | Count |
|---|---|
| `/alternatives/[slug]` | 197 |
| `/compare/[a]-vs-[b]` | 115 |
| `/category/[slug]` | 13 |
| Crawlable pagination | 9 |
| Dynamic OG images | 197 |

> **I deviated here deliberately.** The audit suggested 300+ comparison pages; generating every
> combination would produce thin duplicates — a doorway-page risk the same audit warns about. I
> curate pairs by category + prominence instead, and every generated page carries genuine unique
> content (per-pair differentiators, capability matrix, tailored FAQ), not a template with a name
> swapped in. Category pages have hand-written editorial copy.

Also added: `/feed.xml`, `/llms.txt`, `/manifest.webmanifest` (all previously 404), canonical +
`noindex` on faceted URLs, real `lastModified` dates, AI-crawler rules in `robots.ts`.

## 🎨 Design & accessibility

- **Art direction** moved off the generic purple "AI SaaS 2023" template to a professional
  video-tool language: neutral graphite `#0E0F12`, single amber accent, monospace tabular numerals.
- **Fonts** — none were defined at all (site rendered in three different system fonts). Added
  `next/font` Inter + JetBrains Mono, self-hosted.
- **Type scale enforces a 12px floor** — the codebase had dozens of `text-[9px]`/`[10px]`/`[11px]`.
- **a11y:** skip link, `aria-expanded`, Escape/outside-click handling, focus-visible ring, labelled
  form controls, `role="group"` for button groups, `prefers-reduced-motion` incl. scroll behaviour.
  `eslint-plugin-jsx-a11y` now enforces this in CI.
- Filter counts on every option, removable chips, ⌘K search, custom 404 with recovery paths.

## 💡 Things I added that weren't in the audits

- **`scripts/validate-data.mjs`** — encodes each failure mode found here as a CI check so they can't
  silently return: duplicate slugs, known-dead hosts, guessed affiliate params, unbacked evidence
  claims, out-of-range scores, graveyard recommending a dead tool.
- **Graveyard as a data source** — dead tools are excluded from `ALL_TOOLS` *automatically* from a
  single file, so a dead tool can never be recommended again. Tool pages cross-link to what they replace.
- **`.env.example`** fully commented, explaining what breaks without each variable.
- **Honest empty states** — the homepage says outright that testing is just starting. Trustworthy
  beats impressive on day one.
- **Fixed silent data loss** — `/templates` and `/jobs` waitlist forms called `setSubmitted(true)`
  with *no network request*, showing "you're on the list!" while discarding the email. Now wired to
  the real endpoint, and both `noindex` while empty.
- **Cookie banner honesty** — it asked consent for "optional analytics cookies" that didn't exist.
  Now an accurate notice (Vercel Analytics is cookieless).

## ⚠️ Two things I intentionally did **not** do

1. **I did not fabricate test data.** The audit's Option A ("test 20–30 tools") requires you to
   actually run them. I built the entire system and left it truthfully empty.
2. **I did not switch tool pages to ISR.** It would fix the submission→page flow, but converts 197
   instant static pages into runtime renders. Since submissions need manual review anyway, adding
   them to the data file during review is the better trade. **The admin panel now states this
   limitation explicitly** instead of silently failing.
